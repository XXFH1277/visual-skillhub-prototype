# 详情页工作流

先区分用户确认事实、参考图可见外观与未知信息。按逐张模块计划执行，从整体展示到特点、细节与场景形成阅读顺序；不凭空补写承诺、好评、认证或对比数据。
每张独立生成 1:1 底图，一张图只承担一个模块目的。hero 保留完整轮廓；detail 展示可见部件；benefit 用可见结构支持已确认事实；context 表达可信使用环境；closing 以简洁整体形象收尾。
视觉说明不能覆盖商品身份和事实约束。若某性能无法用参考图证实，保持中性展示，文字由用户确认的模块文案说明。
同套底图保持固定商品身份、光线方向、背景色温和品牌强调色。相邻模块通过构图重点区分，不伪造新角度。
底图不新增标题、价格、徽章、数字或营销文字，保留商品本来存在的标签。标题与正文由工作台程序排版，不让图像模型拼长图。
输出数量与已确认模块一一对应。检查裁切、身份漂移、意外文字与重复构图。事实或结构不明确时采用保守画面，不额外发起自动重生。

## 参考与运行适配

运行器加载归档 `ecommerce-detail-page-generator/SKILL.md` 的“Product Analysis”，`references/prompt-recipes.md` 的“Hero”“Detail Macro”“Lifestyle”，以及按本次品类选择的 `references/category-playbooks.md` 章节。
这些参考用于视觉分析与构图，数量以用户确认的 2–6 模块为准。网站使用 sharp 而非原项目 Python 脚本排版。没有自动联网验证平台政策，结果为待审核设计稿，不宣称自动符合最新上架要求。
